"What tables and relationships must exist for these endpoints to work?"

Hint:
Don't just start writing SQL yet.
The useful engineering exercise is to derive the schema systematically.


1. For each endpoint, identify:

| Question                     | Example                             |
| ---------------------------- | ----------------------------------- |
| What entities does it touch? | `users`, `events`, `bookings`       |
| What fields does it need?    | `user_id`, `event_id`, `created_at` |
| What relationships exist?    | User → many bookings                |
| What constraints exist?      | One booking per user/event          |
| What needs an index?         | `bookings.user_id`                  |
| What must be transactional?  | Creating a booking                  |

Then you consolidate those requirements into one coherent
relational model.


USERS

    GET     /users                          (get all users)
    GET     /users/:id                      (gel a specific user)

EVENTS

    GET     /events                         (get all events)
    GET     /events/:id                     (get a specific event)

AVAILABILITY

    GET     /events/:id/availability        (get availability of a specific event)

BOOKINGS

    GET     /users/:id/bookings             (what bookings the user already has)
    POST    /events/:id/book                (create a booking for a user)
    DELETE  /bookings/:id                   (cancel a booking for a user)


------------------------------------------------------------------------------------


CONSTRAINTS

| Column                | Question                                     |
| --------------------- | -------------------------------------------- |-------------------------
| `users.email`         | Should it be unique?                         | yes (no reuse)
| `events.venue_id`     | Should it be a foreign key?                  | yes (many events at same venue ok)
| `events.capacity`     | Can it be `0` or negative?                   | >= 0, not < 0.
| `events.end_time`     | Must it be after `start_time`?               | start_time < end_time
| `bookings.user_id`    | Must reference an existing user?             | no user-less bookings!
| `bookings.event_id`   | Must reference an existing event?            | no event-less bookings!
| `(user_id, event_id)` | Can the same user book the same event twice? | no! double booking is wrong!
| `created_at`          | Should PostgreSQL provide the default?       | yes. dont want custom timestamps
